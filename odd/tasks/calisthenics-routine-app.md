# Feature: calisthenics-routine-app

Objetivo: web app generadora de rutinas semanales de calistenia militar para casa.
Branch: feature/calisthenics-routine-app | Entrega: work-unit commits convencionales en la rama | Runner: `npx vitest run` + `npm run build`.

## Specs

- S1 (usuario, verbatim): "Crea una app para generar una rutina de ejercicios, de calistenia militar para casa" — genera un plan semanal (calentamiento + bloque principal + vuelta a la calma por día) sin equipamiento de gimnasio (silla/mesa del hogar permitida).
- S2 (usuario, verbatim): "con imagenes y animaciones de cada ejercio" — resuelto en clarificación como "SVG animados propios + enlace/embed de video demostrativo". Cada ejercicio muestra figura stick-figure SVG animada con CSS y enlace "Ver demostración" (búsqueda de YouTube, URL determinística).
- S3 (usuario, verbatim): "Basada en la edad, peso, dias por semana, tiempo de rutina, tipo de cuerpo (delgado,grueso, obeso,etc), objetivo (bajar de peso, ganar musculo, atletico), enfoque en pecho, pierna, brazo, core(abdominales) y niveles de esfuerzo y dificultad (basico, intermedio y avanzado)". La rutina se personaliza con los 8 parámetros; obeso o edad ≥50 filtra ejercicios de alto impacto (suposición marcada como tal).
- S4 (clarificación respondida): plataforma "Web app (React + Vite)"; persistencia "Sí, localStorage" (perfil + rutina + progreso).
- S5 (usuario, verbatim): "Para la implementacion recuerda usar ODD y TDD" — test-first donde exista test determinista con resultado esperado claro (motor de generación); checks proporcionales para UI (build + revisión visual).
- S6 (usuario, verbatim): "Las animaciones de \"Flexiones inclinadas (silla)\" y \"Flexiones\"; Plancha abdominal y Plancha lateral, se ven iguales" — cada variante de ejercicio debe tener pose/animación distinguible.
- S7 (usuario, verbatim): "Toma en consideracion este site https://calisteniamilitar.site/" — funnel tipo quiz: una pregunta por pantalla con tarjetas grandes y rangos de edad (18-29/30-39/40-49/50+). Adoptado en ProfileForm como wizard de 8 pasos con auto-avance.
- S8 (usuario, verbatim): "Puedes revisar y ver si es factible mejorar las animaciones de la app" + "las figuras animadas también se puede mejorar" + "Procede, bajo ODD y TDD" — mejorar animaciones en dos unidades: figuras (ciclos de extremidades interpolados, squash & stretch, sombra de suelo, desfase por tarjeta) y UI (entradas de pantalla/cards, modal con salida, transiciones explícitas, reduced-motion extendido). Sin dependencias nuevas: solo CSS/keyframes.
- S9 (usuario, verbatim): "Puedes explorar la opcion de colocar un reproductor minimalista, para que acompane la seccion con musica libre para entrenar" + aclaraciones: tracks estilo workout del proveedor incompetech.com (sin Mixkit, sin descargas) — sección "Música libre para entrenar" en la vista de plan + barra de reproductor fija global; streaming CC BY 4.0 de Kevin MacLeod, manifest editable en data/tracks.ts.
- S10 (usuario, verbatim): "Agrega la opcion de activar un temporizador, que este de acuerdo con el tiempo de la rutina indicada, el tiempo del temporizador puede ser editable. El temporizador como el reproductor deben permancer visibles, mientras se va navegando por la rutina de ejercicios." — timer con preset = estimatedMinutes del día abierto, minutos editables (input 1-240, bloqueado en marcha), beep WebAudio al finalizar; dock fijo inferior compartido con MusicBar para persistir entre pantallas.
- S11 (usuario, verbatim): "El timer deber deberia sonar por la ejecucion de cada ejercio, es decir si me toca un ejercicio de 35s, sonar cuando cumpla este tiempo para que me indique pare, y pueda continuar con el siguiente paso que puede ser un nuevo ejercio o descanso." + clarificación: "Automatico por defecto, pero con la opcion de cambiar a semi" — timer guiado por pasos (buildSteps: warmup → main×rounds con descansos → cooldown), beep al cumplir cada paso, modo Auto (reps usan estimación 2.5s/rep) / Semi (pasos por reps son compuertas manuales que muestran la dosis hasta continuar).
- S12 (usuario, verbatim): "Cuando suena el beep este puede durar 1 a 3s y bajar el volumen del reproductor, si se esta ejecutando, por ese periodo" — beep extendido a ~2s (pulsos 880Hz cada 0.5s, AudioContext cerrado al finalizar) + player.duck() baja volumen a 18% durante el beep y restaura.
- S13 (usuario, verbatim + captura): "verificar los titulos responsivos del timer no se ven bien en formato movil" — en ≤720px el step-info ocupaba ancho mínimo y el meta se partía; fix CSS con flex-wrap + order: fila 1 nombre completo, fila 2 tiempo + chips + controles compactos.
- S14 (usuario, verbatim): "sobre los tracks offline, considera sites para descarga de mp3s libres, con temas de gym, workout, motivation en electronica y/o rock. Estos archivo mp3 se deben excluir de git, pero se debe consider un indice para su descarga, cuando se clone el repositorio. El usuario debera elegir si desea descargar estos recursos o no, al iniciar la app, siempre y cuando aun no se haya descargado. Esta opcion puede ser cambiada desde su perfil u omitir explicitamente la descarga al inicio" + "considerar tambien electronica" — 9 pistas Mixkit (5 EDM + 4 rock, dl:true en tracks.ts) descargables a Cache Storage (cm-audio-v1); CORS verificado: mixkit assets OK (*), incompetech sin CORS → solo stream. Prompt modal al inicio si pref 'ask'/'yes' y faltan pistas; 'Omitir' persiste 'no' en cm:musicdl:v1; paso 9 del wizard de perfil (musicDownload) permite cambiarla; 'no' limpia el caché. MP3s excluidos vía .gitignore (*.mp3, public/audio/).
